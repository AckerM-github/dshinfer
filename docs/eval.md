# 评测：26 个用例，一条命令，能复现的分数

> 没有评测，“优化”就只能靠感觉。这一层不产出功能，产出**判断力**。

## 1. 组成

| 文件 | 作用 |
|---|---|
| `eval/cases.jsonl` | 26 个用例，14 个类别，一行一个 JSON |
| `eval/judge.py` | 判定器：8 种规则 + 真跑代码 |
| `eval/run_eval.py` | 发请求、记账、出表、存档 |
| `tests/test_judge.py` | 判定器自身的 11 个单测（判定写错会让整份评测失真） |
| `eval/results/*.json` | 每次运行的完整记录（含失败用例的完整回答） |

类别：事实 2、推理 2、数学 2、格式 2、代码 2、指令遵循 2、边界 2、长上下文 2、工具调用 3、代码执行 3、解释 / 翻译 / 细粒度 / 写作 各 1。

## 2. 判定优先级

1. **规则**（能判就不问模型）：`contains_all`、`contains_any`、`exact`、`regex`、`json`、`tool_call`、`no_tool_call`、`length_between`。
2. **执行**（唯一能证明代码对不对）：`python_runs` —— 把回答里的代码抠出来，拼上隐藏断言，用 `python -I` 在临时目录里跑，看是否打印 `OK`。超时 15 s、隔离模式、不联网。
3. 模型评分：**暂不使用**。同一模型自评有偏，且会让评测成本翻倍、结果不可复现。

## 4. 唯一失败：模型把 4 空格缩进写成了 1 空格

```
✗ code-fizzbuzz-exec  IndentationError: expected an indented block after 'for' statement on line 3
   def fizz(n):
    result = []              ← 只有 1 个空格
    for i in range(1, n + 1):
    if i % 15 == 0:          ← 和 for 同层，for 没有 body
```

排查过程：先怀疑自己的服务在压平缩进，直连引擎（`:8124/completion`）得到同样的 1 空格 → 排除服务层；再用两个对照 prompt 验证：

- `原样输出 A    B（四个空格）` → `'A    B'` ✅ 空格没被吞
- `写 def f(): 第二行缩进四个空格写 return 1` → `'def f():\n    return 1'` ✅ 四空格正常

结论：**不是工具链问题，是模型自己写的**——不显式要求缩进宽度时，它偶尔每行只给 1 个空格。这种错误字符串匹配（`def fizz`）永远抓不到，只有真跑代码才会暴露。这正是引入 `python_runs` 的理由。

## 5. 覆盖与盲区

覆盖：事实召回、两步推理、算术、格式遵循、否定指令、不确定表达、长上下文取针（1.1K token）、工具调用的三种状态（该调 / 调对参数 / 不该调）、代码可执行性。

盲区（下一步）：
- **多轮**：目前全是单轮，没有指代消解、没有上下文继承。
- **长文档**：取针测到 1.1K token，没测 8K/16K 的衰减曲线。
- **安全边界**：只测了"不知道就说不知道"，没测越界请求。
- **统计意义**：26 例只能抓"明显退化"，抓不到 3% 的波动。同一用例重复 5 次取多数会更稳，但成本 ×5。

## 7. 怎么用它做决策

1. 改 prompt 模板 / 换量化档 / 调采样参数 → 先跑评测，再看分数，避免"我觉得变好了"。
2. 失败用例优先看 `eval/results/*.json` 里的 `answer_full`，那是模型原话。
3. 新增能力（比如 agent 循环）先加用例，再加实现——用例就是验收标准。

## 8. 已知模型缺陷：代码缩进只有一个空格

26 例里唯一稳定失败的是 `code-fizzbuzz-exec`，原因是**模型写 Python 时默认只用 1 个空格缩进**，执行必然 `IndentationError`。排查与绕法（都是实测）：

| 实验 | 结果 | 结论 |
|---|---:|---|
| 直接让它写函数（5 次采样） | 22/22 行都是 1 空格 | 不是偶发，是默认习惯 |
| system 里写"必须用 4 个空格" | 仍是 1 空格 | 规则句无效 |
| prompt 里给一段 4 空格的代码让它**抄写** | 2/2 行都是 4 空格 | 词表支持，不是量化坏了 |
| **few-shot：给一个 4 空格的示例** | **4 空格** | ✅ 有效绕法 |
| 要求用 `\t` 缩进 | 真的输出 tab | 说明这是"风格选择"，不是能力缺失 |

**绕法**：需要模型产代码时，在 system 或首轮对话里放一个 4 空格缩进的示例（不是一句规则），它就会跟随。
**含义**：这类缺陷用字符串匹配（`def fizz`）永远抓不到，只有 `python_runs` 真跑一遍才暴露——这也是判定器里保留"真执行"的原因。
